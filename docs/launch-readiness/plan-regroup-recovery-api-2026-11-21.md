## 1. Verdict

No. Regroup can't take a live payment today, and nothing that blocks it is code that's still missing.

**Production's functions are bound to the wrong Stripe account.** `STRIPE_SECRET_KEY@3`, the only version they use, authenticates as the "Homegroups App" account `acct_1RNFH5ID2FGlm411`. None of Regroup's prices exist there, so tier checkout, Connect and rent all fail (MS-01). The owner added Regroup's own key as version 7 on 2026-11-22, but production only uses it after a redeploy.

The redeploy is overdue for other reasons too. Production runs `main` as of 2026-11-11, so it's missing:

- P4a billing, #160, documents, Mark Resolved, and the rules and indexes the new app needs;
- `CONNECT_BASE_URL`, without which Connect onboarding throws;
- the web hosting's `/connect` rewrites.

Two engineering gaps also sit between the deploy and a resident paying rent:

- **Invitation emails link to a page that doesn't exist** (`/redirect`), so no resident can follow an invite.
- **The iOS app takes card details in in-app WebViews,** which the launch design itself expects App Review to reject.

After that, it's store builds and review, a privacy policy that's still a draft, and a short list of Stripe Dashboard settings.

## 4. Risks

- **High: a deploy binds an unverified key or config.** B2 is the first production deploy since the key fix and the env change. Run B3 straight after it, before opening sales (B4).
- **High: housemates can read each other's recovery, legal and money data** (M5), with nothing more than their own credentials and the SDK.
- **High: the iOS build is rejected** for in-app card entry (B6), which delays B7 by a review cycle.
- **High: the publishable keys may belong to the old account** (B3b). If so, every card confirm fails, even with B2 done.
- **Medium: production is open for checkout today** (pre-P4a, no sales switch). It fails only because of the wrong key, so fixing the key without B2's sales gate would open sales immediately. Deploy `main` (with the switch), not a key-only change.
- **Medium: personal data has been public** since the repository went public (M1).
- **Medium: "no live users" is the owner's statement, not a production read.** If it's wrong, the redeploy breaks the current store build for real users, and backfills come back into scope.
