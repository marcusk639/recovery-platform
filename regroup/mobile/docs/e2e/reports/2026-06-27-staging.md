## Root causes found and fixed this session

### 1. `offlineQueue.ts` — Metro dependency-map hoisting crash (FIXED)

**Symptom:** "Uncaught Error: Requiring unknown module 'undefined'" in `offlineQueue.ts:55`
after Maestro launched the app. Error overlay blocked navigation to `login-screen`,
causing 100% of login-dependent flows to fail immediately.

**Root cause:** `tryGetAsyncStorage()` used a string-literal `require('@react-native-async-storage/async-storage')`.
Metro's static collector registered an unresolvable slot in the dependency map for the
non-installed package. Metro substituted `undefined` for the module ID, so the runtime
call became `require(undefined)` → uncaught crash (same mechanism as the netinfo bug
fixed in `useOfflineSync.ts` via commit `6e0d615`).

**Fix (`regroup/mobile/src/services/offlineQueue.ts`, `tryGetAsyncStorage`):**
Aliased `require` to `dynamicRequire = require as (name: string) => unknown` so Metro's
static collector skips the call. The catch block now runs as designed, logging the warning
and falling back to in-memory queue. Identical pattern to the netinfo fix.

### 2. `login.yaml` — email-input timing (FIXED)

**Symptom:** "Element not found: email-input" immediately after `login-screen` is visible.

**Root cause:** Formik `Field` components register with the iOS accessibility tree
asynchronously after the screen container mounts. Asserting `login-screen` visible only
proves the SafeAreaView wrapper is in the tree — the inner Formik fields take additional
time.

**Fix (`maestro/subflows/login.yaml`):** Replaced `assertVisible: login-screen` +
immediate `tapOn: email-input` with `extendedWaitUntil` for `login-screen` (15s) followed
by a second `extendedWaitUntil` for `email-input` (10s) before tapping.

## Remaining blockers

### B1 — XCTest driver instability (infrastructure, not app)

Every 2–4 sequential `maestro test` invocations the XCTestRunner crashes
(`Connection refused /127.0.0.1:<port>` or `iOS driver not ready in time`).
Requires `pkill -f idb_companion` + simulator reboot to recover.

**Impact:** Cannot reliably run the 14-flow suite sequentially in one shell session.

**Recommended fix options (pick one):**

1. **Maestro Cloud** — single-flow suite runs in parallel on Maestro's cloud VMs;
   eliminates local XCTest instability entirely. CI job `maestro-smoke` already
   wired (commit `b1bcaa1`).
2. **`run-all.yaml` master flow** — chain all flows with `runFlow:` in a single
   Maestro session (one XCTest session, never torn down between flows). The
   mobile-e2e skill templates section documents this pattern.
3. **Simulator reset between runs** — add `xcrun simctl shutdown / boot` between
   invocations in the shell script; slower but more reliable locally.

### B2 — login.yaml `email-input` wait — not yet run to completion

The `extendedWaitUntil` fix for `email-input` was applied but the subsequent
`guest-home` run timed out on XCTest startup (B1) before it could reach the
email-input step. Needs one clean run to confirm.

### B3 — Splash error toast persists onto login screen

Screenshot from 2026-06-27_213821 shows "Something went wrong. Please try again."
on the login screen — the anonymous-auth failure toast from Splash is still visible.
This is cosmetic (not a functional blocker; the form fields are present), but
warrants a clean dismiss before Maestro types credentials.
**Suggested fix:** add `tapOn: text: "Dismiss"` or `tapOn: id: "error-dismiss"` in
login.yaml after the login screen appears, with `optional: true`.
