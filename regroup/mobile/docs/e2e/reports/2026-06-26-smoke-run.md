## Failure

### 00 — smoke (FAILED)

**Maestro error:** `Assertion 'id: initial-landing-screen is visible' failed` after
`Launch app … with clear state (IS_E2E_TEST=1) … COMPLETED`.

**On screen instead (screenshot `2026-06-26_192043`):** the **Splash** screen — `RatsLogo`

- the `DeepLinkTester` dev overlay (rendered because `__DEV__`) — with a red in-app toast
  `ERROR: Spla…` (matches `logError('Splash - Authentication failed:', …)`).

**Root cause (traced, not guessed):**
`withSplash` (`src/screens/Splash/Splash.tsx`) renders the Splash view while `!appIsReady`
and only swaps to the real app (→ `InitialLanding`, which owns `initial-landing-screen`)
once `appIsReady` is true. `appIsReadyCheck()` (Splash.tsx:191) returns true **only when
`userState.user || userState.invitation`**. A clean E2E launch has neither, so readiness
depends on the anonymous-login fallback: `loginIfNecessary` (Splash.tsx:179) →
`anonymouslyLoginHandler()` must populate `userState.user`. It isn't — so `appIsReady`
stays false and the app is stuck on Splash forever. The `Splash - Authentication failed`
toast indicates the auth/anonymous path is erroring against the Auth emulator.

**This gates the entire suite:** all 14 flows require the app to get past Splash, so
running them now would reproduce the same failure 14×. Fix the Splash auth gate first.

**Classification:** Auth (anonymous sign-in not completing in E2E mode).

**Recommended next step (owner: app/auth):** instrument the launch auth chain —
`authUser()` → `dispatch(autoLogin(...))` (Splash.tsx:238–244) and
`anonymouslyLoginHandler` — to see whether (a) `authUser()/autoLogin` throws before the
anonymous fallback runs, or (b) `signInAnonymously` itself rejects against the Auth
emulator. Confirm the Auth emulator allows anonymous sign-in and that no listener resets
`loginFailed` before `loginIfNecessary` fires. NOTE: this code was under active edit by a
concurrent session at the time of this run — coordinate before changing it.
