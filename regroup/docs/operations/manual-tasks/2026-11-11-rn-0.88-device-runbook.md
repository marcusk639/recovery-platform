## Steps

### 1. Install the Debug build on the iPhone

**Where:** Xcode, `regroup/mobile/ios/rats.xcworkspace`.

Pick the **rats** scheme, the **Debug** configuration and your iPhone, then press **Run**. Allow notifications when asked. Sign in with your Test House account.

**Expected result:** the app opens on your house. The Xcode console stays open for step 2.

---

### 2. Real push delivery on the iPhone (row 3)

**Why by hand:** the simulator can't receive APNs pushes through FCM for the e2e builds, so `push.sh --sim` proves only how the app handles a push, not that one arrives. It also refuses silent pushes (`content-available` with no alert: "no user visible content"), so the simulator checks only the admin alert banner. Whether the app survives a data-only push, and how it shows a resident push, is checked only here.

> **Needs the token fix (PR #251).** Before it, the app never saved its FCM token to `users/{uid}.messagingToken`, so step 2.1 finds no token. Install a build that includes #251.
>
> **Resident pushes in the background:** until 2026-11-11 the server sent resident pushes (`sendNotification`) as data-only messages and the app's background handler did nothing, so they showed only while the app was open. #253 added a notification block the OS shows in the background; `notify`, `onGuestWrite` and `rentCharges` were redeployed to `phoenix-cleanhouse` from `main` that day. An iOS build without the follow-up app fix shows a resident push twice while the app is open. The console's test messages below always carry a notification block, so they show in the background either way.

**Where:** the Firebase console for `phoenix-cleanhouse`.

1. In **Firestore → `users` → your user document**, copy the last entry of `messagingToken`.
2. In **Messaging → New campaign → Notifications → Send test message**, paste the token. Send each of these and watch the phone:
   - (a) with the app **open**: title `RN088 foreground`;
   - (b) with the app **in the background** (swipe up to the home screen): title `RN088 background`;
   - (c) with the app **open**, a message with only a custom data key `probe` = `1` under **Additional options → Custom data**, and no title or text. The console needs a title, so use `RN088 data` and check that the app doesn't crash; the banner appearing is fine.

**Expected result:** (a) shows a banner over the app; (b) shows on the lock screen or in Notification Center; (c) the app keeps running.

---

### 3. Universal links on the iPhone (row 7)

**Why by hand:** `regroup-app.com`'s AASA file lists only `D8K3FS4HAX.com.rats.dev`, so only a production-signed build opens these links. The e2e builds can't, and Maestro must never drive the production build.

**Where:** the Notes app on the iPhone. Paste this into a note, then tap it (don't paste it into Safari's address bar, which never opens apps):

```
https://regroup-app.com/?type=invitation&invitationType=guest&house=test-house-123&inviter=test-manager&email=e2e-invitee%40rats-e2e.com&owner=&initialPhase=
```

1. Force-quit the app (swipe it away), then tap the link.
2. With the app in the background, tap it again.
3. Background the app, open another app for a few seconds, then come back.

**Expected result:** 1 and 2 open **Regroup**, not Safari. With a signed-in account, the app comes forward (the invitation itself is checked by the custom-scheme suite). 3 resumes on the same screen, with no reset or crash. If Safari opens instead, long-press the link: when the menu offers **Open in "Regroup"**, the link works and iOS only remembered an earlier "open in Safari" choice.

Don't finish an invitation signup from this link: `test-house-123` doesn't exist in production, so it just ends on an error.

### 4. Android universal links: record as a known failure (row 7)

Nothing to run. `https://regroup-app.com/.well-known/assetlinks.json` names the package `com.rats.dev`, but the Android app is `com.regroup.app`, so Android never verifies the link and opens the browser. This is the same on `main` and isn't caused by the upgrade. Record it as **fail (same on main)**. Fixing it means adding `com.regroup.app` with the Play app-signing key's SHA-256 fingerprint to that file, a hosting deploy, for launch plan P5.

**Expected result:** row 7 Android reads "fail, same on main: assetlinks.json names com.rats.dev".

## Rollback

All steps are non-destructive and can be re-run. The test pushes go only to your own token. Delete the Debug app afterwards if you want the App Store build back.

## Notes & Gotchas

- **The Debug build signs in to production.** Use only your Test House account.
- **Never point Maestro at a production build.** The guard refuses it, and it refuses while `com.rats.dev` or `com.regroup.app` is installed on a test simulator or emulator. These steps are by hand, on your own phone.
- A universal link typed into Safari's address bar never opens an app. Tap it from Notes or Messages.
- The Firebase console's **Send test message** always includes a title, so it can't send a true data-only push. The automated Android check (`push.sh --device`) sends real data-only pushes; on iOS nothing does yet, because the simulator refuses them.
