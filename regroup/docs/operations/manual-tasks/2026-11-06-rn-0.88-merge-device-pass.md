# RN 0.88 upgrade: manual device pass and merge (PR #160)

> **Date:** 2026-11-06
> **Author:** Claude Code (review before following)
> **Estimated time:** about 2–3 hours, both platforms
> **Risk level:** Medium. The Debug build signs in to **production** (`phoenix-cleanhouse`), so use only your own Test House account.

## Context

PR #160 upgrades `regroup/mobile` to React Native 0.88.1. Everything that can be automated is done and recorded in `regroup/mobile/docs/build/react-native-0.88-upgrade.md` §7.2:

- parity flows on the iOS simulator and Android emulator;
- the RN 0.72 baseline;
- the store-build guards;
- the Task 17 gate revert, plus the whole-branch gate;
- Gradle wrapper validation.

What's left needs real devices. Native changes (notifications, file system, gestures, edge-to-edge layout, links, Hermes `Intl`) can break in ways simulators don't show. The launch design (§4.4) makes this device pass a condition of merging #160.

## Prerequisites

- [ ] An iPhone and an Android phone. If possible, one Android device on Android 15 or later, plus access to an API 30 device or emulator for the layout check.
- [ ] A Mac with Xcode, CocoaPods, Node 22, JDK 17+ and the Android SDK.
- [ ] You can sign the iOS app with your Apple developer team.
- [ ] A checkout of the `chore/regroup-rn-upgrade` branch, at or after `3e07ae25`, with `cd regroup/mobile && npm ci`. The postinstall runs `patch-package` and `pod install`.
- [ ] Your existing `regroup/mobile/.env`, with the test-mode Stripe key and the Maps key. **Never put a `pk_live_` key in it**, and never commit it.
- [ ] Your own production Test House operator account. Use no real resident or operator data.
- [ ] For the simulator section: the iOS `E2EEmulator` build and the local emulators (`./scripts/test-prep.sh`), as in `regroup/mobile/maestro/README.md`.

## Steps

### 1. Build and install the Debug app on both phones

**Where:** `regroup/mobile` on the upgrade branch.

- **iOS:** open `ios/rats.xcworkspace` in Xcode, pick the **rats** scheme and the **Debug** configuration, select your iPhone, and press **Run**. Keep the Xcode console open.
- **Android:** with the phone plugged in and USB debugging on, run:

```sh
npx react-native start            # terminal 1 (Metro)
npx react-native run-android --mode debug   # terminal 2
```

**Expected result:** the app launches to the landing screen on both phones.

**iOS check, Firebase config pickup:** the Xcode console shows the line `firebase.json found at …`.

---

### 2. Upgrade in place (iOS, optional now; both platforms move to P9 otherwise)

**Where:** iPhone, App Store.

1. Delete the Debug app.
2. Install the current **App Store** version, sign in with your Test House account, and note that you're signed in.
3. Run the Debug build from Xcode over it, which uses the same bundle ID.

**Expected result:**

- you're still signed in, with no forced sign-out;
- a push still arrives (step 3);
- after paying rent, no stale rent reminder is left.

**Android can't be tested this way.** The Play build is signed with the Play key and the Debug build with the debug key, so Android refuses the update. Android, and a proper iOS test through TestFlight, belong to the production pass in launch plan P9, row `DEVP-003`. Record Android as **moved**.

---

### 3. Push notifications

**Where:** the Firebase console for `phoenix-cleanhouse`: **Firestore**, then **Messaging**.

1. Sign in on the phone with your Test House account. In **Firestore → `users` → your user document**, copy the `messagingToken` field.
2. In **Messaging → New campaign → Notifications → Send test message**, paste the token and send:
   - (a) a **notification** message while the app is open in the foreground;
   - (b) on Android, a notification while the app is in the **background**;
   - (c) a **data-only** message (custom data key and value, no title or body) while the app is in the foreground.
3. Schedule a rent reminder in the app, then cancel it.

**Expected result:**

- (a) shows in the app;
- (b) lands in the Android `default` channel (long-press the notification and choose **Settings** to see the channel);
- (c) reaches the app without crashing it;
- the reminder fires when scheduled and doesn't fire once cancelled.

---

### 4. Files and reports

**Where:** the Debug app, signed in as your Test House operator.

- **Document upload:** upload a dummy PDF to your own resident profile. Start a second upload, then **cancel** it.
- **CSV guest import:** import a small CSV of fake test names.
- **PDF export (Android):** export a compliance PDF and open it.

**Expected result:** the upload appears and opens; the cancelled one doesn't appear and nothing crashes; the import shows the fake guests; the PDF opens. Afterwards, delete the dummy guests and documents.

---

### 5. UI

**Where:** the Debug app, on both phones.

- **House search with location:** grant location permission. Houses appear.
- **Both charts:** the house hub and the stats screens draw them.
- **Date-picker modal:** open it, pick a date, close it.
- **Modal swipe dismiss:** swipe down on a modal, such as a dispute or confirm sheet. It closes.
- **Android 16 back gesture,** if you have an Android 16 device: back closes screens and modals in order, and doesn't exit unexpectedly.
- **Keyboard:** on each screen in decision record §5.3, the keyboard doesn't cover the field being typed in.

**Expected result:** each behaves as described, with no crash and no layout jump.

---

### 6. Layout (Android)

**Where:** an Android 15+ device, and an API 30 device or emulator.

**Expected result:** no content sits under the status bar or the navigation bar. Content uses the insets correctly on both.

---

### 7. Links

**Where:** both phones.

1. With the app **closed**, open a universal link (`https://regroup-app.com/…`) from Notes or Messages. Then open a custom-scheme link (`regroup-app://`).
2. With the app **in the background**, open a `regroup-app://` link.
3. On iOS, send the app to the background, open another app, and come back.

**Expected result:** the app opens to the link's destination each time. Resuming from the background doesn't reset it or crash.

> **Note:** an invitation link from a real email currently dead-ends on `regroup-app.com/redirect`, a known issue that launch plan P5 fixes. Test with links you construct, not with invitation emails.

### 8. Dates on iOS (Hermes `Intl`)

**Where:** both phones, side by side.

**Expected result:** week start and end on the resident home week summary, and the times on activities, match between iOS and Android. If you can, test across a DST change (set the phone's date near the next DST change).

### 9. Signup and dispute (on the iOS simulator, not production)

**Where:** the iOS simulator, with the `E2EEmulator` build and the local emulators (`maestro/README.md`). Their Maestro flows are stale (decision record §7.2), so these are checked by hand.

1. **Signup:** go to **Sign up**, fill in the form, **tick the terms box**, and submit.
2. **Dispute:** sign in as `test-guest-a@rats-e2e.com` (the seeded account), open **Activities**, tap **DISPUTE** on another resident's activity, enter a reason, and submit.

**Expected result:** signup lands on **NewAccount** (or OrgSetup for a manager). The dispute is submitted, and the activity shows as disputed.

## Notes & Gotchas

- **The Debug build signs in to production.** Use only your Test House account, and don't create data for real houses.
- **Never point Maestro at a production build.** The repo's guard refuses it, and it also refuses while `com.rats.dev` or `com.regroup.app` is installed on a test simulator or emulator. Device testing by hand, as here, is outside the guard.
- **`npm ci --ignore-scripts` skips `patch-package`.** If you use it, run `npx patch-package` afterwards, or the `react-native-modal` patch is missing.
- **Android builds of RN 0.72 (`main` before this merge) need JDK 17.** RN 0.88 builds fine on JDK 21.
- An Android flow (`operator-manual-payment`) hung once in 7 automated runs on a blank screen when the app relaunched. If you see a blank white screen on relaunch on a device, note it in step 10.
